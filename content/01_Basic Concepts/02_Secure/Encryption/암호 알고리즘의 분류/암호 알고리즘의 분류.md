# 암호 알고리즘
> Cipher Algorithm

[[암호화와 복호화|암호화 혹은 복호화]]를 수행하는 방법론들.
즉, **[[평문]]과 [[암호키]]를 이용해 암호문을 만들거나 이를 풀어내는 일련의 과정 및 방법들을 말한다.**

## 단방향 알고리즘
![[image-1.png]]

**단방향 알고리즘**은 문자 그대로 일방 통행, 즉 **[[평문]]을 [[암호키]]를 이용해 [[암호화와 복호화|암호화]]한 후 그 암호를 복호화할 수 없는 알고리즘을 말한다.** 

**암호학적 해시 함수**와 **비암호학적 해시 함수**로 분류된다. 이 둘 모두 [[해시 함수#암호학적 분야의 해시 함수|해시 함수]]를 사용한다.

|     구분     |           암호학적 해시 함수            |     비암호학적 해시 함수     |
| :--------: | :-----------------------------: | :-----------------: |
|   **목적**   |          **보안 필수 용도**           |  **보안이 필요 없는 용도**   |
|   **기준**   |      충돌 / 역상 저항성 등 보안성 확보       |    속도와 충돌 분포 최적화    |
| **충돌 저항성** |      매우 높음. 의도적 충동 생성 어려움       |   상대적 낮음, 가능성 존재    |
| **역상 저항성** |         있음(원본 유추 거의 불가)         |    없음(원본 유추 가능)     |
|   **속도**   |             상대적 느림              |        매우 빠름        |
|   **목적**   | SSL / TLS, 디지털 서명, 비밀번호 해싱 등 보안 | 빠른 데이터 검색 / 분류, 체크섬 |

#### 암호학적 해시 함수
> Cryptographic Hash Function

일반적으로 암호학에서의 [[해시 함수]]를 지칭하면 이를 말한다. 
암호학적 해시 함수는 **보안을 강조**하기에 반드시 **[[역상 공격]]과 [[해시 함수#해시 충돌|해시 충돌]]에서 안전해야 한다.**

즉, 입력값과 해시값에 대해
1. 서로 다른 입력값이 동일한 해시값을 만들지 않고,( ->충돌 저항성)
2. 입력값을 찾기 어렵게 만들어야( ->역상 저항성)
한다.

이를 활용해 해시값은 [[정보보안#무결성|무결성]]을 확인할 수 있는 검증 장치로 사용하기도 한다.

다만 이런 복잡한 연산으로 인해 상대적으로 처리 속도가 느리기 때문에 [[네트워크]]에서는 단순 에러 검출용인 [[체크섬]]에서는 사용이 적합하지 않다. 그래서 [[SSL]]이나 [[TLS]]같은 보안 프로토콜에서 안전한 무결성 검증과 인증을 위해 암호학적 해시함수를 사용한다. 이는 악의적인 공격으로부터 데이터를 보호하고, 통신 수신자의 신원을 확인하기 위함이다.

또한 비밀번호 관리에서도 널리 활용한다. [[Linux]]의 경우 비밀번호를 직접 저장하지 않고, 해시 함수를 이용한 변환값만 저장한다. 사용자가 로그인을 시도할 때 비밀 번호를 입력하면 입력값을 동일한 해시 함수로 변환한 뒤, 이를 저장된 해시 값과 비교하는 방식으로 활용한다.

종류는 대표적으로 [[MD 계열 해시 함수|MD 해시]]와 [[SHA 계열 해시 함수|SHA 해시]]가 있다.

#### 비암호학적 해시 함수
> Non Cryptographic Hash Function

비암호학적 해시함수는 상대적으로 **보안성을 요구하지 않는 [[해시 함수]]이다.**
빠른 연산 속도와 낮은 충돌 저항성의 특징을 가진다.

이 연산 속도를 활용해 [[네트워크]]의 [[체크섬]], 낮은 수준의 데이터 무결성 검증, 데이터 분류에서 사용한다.

## 양방향 알고리즘
**양방향 알고리즘은 1개 이상의 [[암호키]]를 이용해 [[암호화와 복호화]]를 할 수 있는 알고리즘을 말한다.**

**대칭키 알고리즘**과 **공개키(비대칭) 알고리즘**으로 분류된다. 그리고 실무적으로는 이 둘의 장점을 합친 **복합 암호 알고리즘**이 있다.

![[image-3.png]]

|     구분      |       대칭키 알고리즘       |            공개키 알고리즘            |
| :---------: | :------------------: | :----------------------------: |
|  **키 사용**   |         같은 키         |            다른 키(분리)            |
|   **속도**    |     상대적 빠름 + 효율적     |          상대적 느림 + 복잡함          |
|   **보안**    |         어려움          |               높음               |
|   **용도**    |   **대량 / 빠른 암호화**    |      키 교환, 인증 등 **보안 강조**      |
| **키 교환 문제** |  키를 안전하게 공유하는 방법 필요  |        공개키는 공개, 개인키는 비밀        |
| **암호화 과정**  | 송 수신자의 동일한 키를 사전에 공유 | 송신자: 수신자의 공개키<br>수신자: 수신자의 개인키 |
#### 대칭키 알고리즘
> Symmetric Key Algorithm ->[[대칭키 알고리즘]]

**대칭키 알고리즘**은 [[암호 알고리즘의 분류#양방향 알고리즘|양방향 암호 알고리즘]]의 한 종류로, **하나의 [[암호키]]를 이용해 [[암호화와 복호화]]를 수행하는 알고리즘**을 말한다.

단, 하나의 키를 이용해 암/복호화가 가능하기 때문에 **키 교환 / 분배 문제**가 발생한다. 

자세한 내용은 해당 포스트를 참고.

#### 공개키 알고리즘
> Public Key Algorithm -> [[공개키 알고리즘]]

**공개키 알고리즘**은 [[암호 알고리즘의 분류#양방향 알고리즘|양방향 암호 알고리즘]]의 한 종류로, **암호와 복호의 키가 다른 방식을 말한다.** [[암호키]]를 두 종류 만든다. 그 중 하나는 보관 / 하나는 공개해 송신자는 공개키로 암호화, 수신자는 보관키로 복호화 한다.
