# IPv4
> Internet Protocol version 4

[[IP - Internet Protocol|IP]]의 네 번째 버전.

버전은 4이지만, 전 세계적으로 배포된 첫 번째 [[인터넷]] [[프로토콜]]이다. **[[패킷]]의 형식을 지정하는 프로토콜**로 보통 IP를 말하면 **IPv4** 혹은 **IPv4 패킷**을 의미한다. 하지만 후술할 **IPv4의 주소 부족 문제**로 인해 IPv4의 한계가 대두되었고, 다양한 기술들을 활용해 이를 극복하면서 동시에 [[IPv6]]로 대체를 준비 중이다.

[[패킷#패킷의 MTU|MTU]]는 기본적으로 1,500바이트. 즉, 헤더(IPv4, TCP기준) 제외 최대 전송 가능 데이터 크기는 1,518바이트이다.

---
## IPv4의 구조
> IPv4 Structure

IPv4는 크게 [[IPv4 헤더]] + [[페이로드]]로 이루어져 있으며 형식은 아래와 같다.

```
[IPv4 Header] + [Paylpad(TCP/UDP Segment)]
```

이 때 [[캡슐화 - Encapsulation|캡슐화]]로 인해 페이로드의 데이터는 [[TCP]] / [[UDP]]의 [[세그먼트]]이다.

#### IPv4의 헤더
> IPv4 Header -> [[IPv4 헤더]]

IPv4 [[패킷]]의 메타데이터를 지정하는 헤더이다. 이 헤더 데이터 내부에는 주로 **패킷의 생존시간([[TTL]])**, 버전, **주소([[IPv4 주소]])**, 그리고 [[Routing Protocol|라우팅]]에 관한 정보를 지니고 있다.

헤더 자신의 오류를 검출할 수는 있으나 페이로드 데이터는 검출하지 않는다.

#### 페이로드(데이터)
> Payload -> [[페이로드]]

IPv4의 패킷에서 헤더를 제외한 순수 데이터 부분. 이 데이터는 상술했듯 캡슐화로 인해 상위 계층의 세그먼트와 데이터가 있다.

현재 **IPv4의 헤더에서는 이 페이로드 부분의 오류를 직접 검증하지 않는다.** 페이로드 부분은 상위 계층 프로토콜이 검증한다.

## IPv4의 주소
> IPv4 Address -> [[IPv4 주소]]

**인터넷 상에서 컴퓨터나 [[네트워크]]장치를 식별하기 위해 사용하는 32비트 길이의 인터넷 프로토콜 주소.** 

OSI 7계층이나 TCP/IP 계층에서는 [[OSI 7 Layer & TCP,IP 4 Layer|네트워크 계층(L3)]]에 속하는 [[식별자]]이다.

일반적으로 **IP** 혹은 **IP 주소**라고 부르면 이 **IPv4의 주소**를 지칭할 정도로 매우 범용적으로 사용된다. 물론 IP와 IP주소, 그리고 IPv4 주소는 서로 연관되어 있지만 다른 개념이다. 아무튼, 약 43억개의 주소를 생성할 수 있지만, 2011년에 고갈되었다. 이후 다양한 방법을 통해 [[IPv6]]로 이전을 준비 중이다.

#### IPv4 주소 고갈 문제
[[IPv4 주소]]의 생성 가능 총 갯수는 약 43억개로 초반에는 [[클래스 기반 네트워크|클래스풀]]한 네트워크로 활용했었다가, 2011년 02월 04일 모든 IPv4 주소가 소진되면서 더이상 **새로운 IPv4 주소는 할당하지 않는다.**

과거 클래스풀 네트워크를 사용하던 시절에는 이 43억개의 주소를 다 소진할 줄 몰랐다 / 아주 오래 걸릴 것이다 라고 예상했었다. 그래서 이 주소들을 아낌없이 펑펑 나눠줬는데, 예를 들어 내가 IPv4 주소 `192.168.10.x`를 요청하면 `192.168.10.0` ~ `192.168.10.255`까지 전부 내 소유의 IP 주소로 등록해버렸다. 그리고 나는 그 중 마음에 드는 번호 몇 개만 실제로 사용하고 나머지의 약 250개는 전부 버리는 주소로 만들었었다. 하지만 IoT의 시대의 도래와 스마트폰의 보급, 그리고 중국과 인도에서 네트워크 활용 등의 상황이 되어 2000년이 되기 전 IPv4에서 IPv6로의 이전 대책을 강구했다. 그에 3 가지 대책이 나왔다.

##### 단기 대책 - CIDER
**단기 대책으로 [[클래스 리스 네트워크|클래스리스(CIDER)]]기반의 주소 체계를 도입했다.** 원래는 [[클래스 기반 네트워크|클래스풀]]했던 주소 체계였지만, 실제로 사용하고 보니 A클래스는 많이 남고, C 클래스는 압도적으로 부족하는 등 그 한계를 체감했고 여기서 주소 낭비도 많았었다.

그래서 클래스를 뛰어넘는 클래스리스(CIDER) 주소 체계로 변환해 단기적으로 대응했다. 대표적인 CIDER 기법으로는 [[서브넷 - Subnet|서브넷 마스크]]가 있다.

##### 중기 대책 - NAT와 사설 IP
[[NAT]]의 PAT를 이용해 외부와 내부, 즉 [[공인 IP와 사설 IP]]로 구분해 중기적인 대책을 세웠다. 정적 NAT와 동적 NAT는 생각보다 IPv4의 낭비를 줄이는데에는 도움이 되진 않았고, PAT가 아주 큰 도움을 주었다.

##### 장기 대책 - IPv6
**장기 대책은 차세대 IP인 [[IPv6]]으로 이전이고, 현재 진행형이다.** 사실 지금은 그 과도기라 IPv6보다는 IPv4의 주소 체계가 우리에게는 더 익숙하고 범용적으로 사용중이다. 그래서 현재는 IPv6를 아예 새로 부여하는 것 보다는 [[IPv6 주소|IPv4 -> IPv6 전환 기술]]을 주로 사용한다.

IPv6는 거의 무한에 가까운 주소 지정이 가능하기 때문에 익숙치 않더라도 언젠간 반드시 가야할 길이다.
