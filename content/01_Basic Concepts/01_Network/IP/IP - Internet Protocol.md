# 인터넷 프로토콜 - IP
> Internet Protocol

[[OSI 7 Layer & TCP,IP 4 Layer|네트워크 계층(L3)]]에서 사용하는 [[프로토콜]]겸 [[식별자]].

컴퓨터 [[네트워크]]에서 **데이터를 주고 받기 위한 표준 규약**으로, 네트워크 상에서 **호스트의 주소 지정과 패킷 분할, 조립 기능을 담당**한다.

IP의 정보는 [[패킷]]이라는 [[PDU]]를 이용해 전송되고, [[Routing Protocol|라우팅]]에 의해 비신뢰성과 비연결성을 지닌다.

- IP 계열
	- 보안: [[IPSec]]
	- 오류 제어: [[ICMP]]
	- 멀티캐스트 그룹 관리: [[IGMP]]

## IP의 비신뢰성과 비연결성 특징
IP는 **비신뢰성**(Unreliability)과 **비연결성**(Connection-Lessness)의 특징을 지닌다. 따라서 이를 해결하기 위해 [[TCP]]와 같은 상위 계층의 프로토콜을 이용해야 한다.

#### 비신뢰성
> Unreliability

[[IP - Internet Protocol|IP]]의 비신뢰적 특징으로는 흐름에 관여하지 않기 때문에, **송신한 정보가 올바른 상태인지 보장할 수 없다**. 그래서 패킷이 중간에 사라지거나, 순서가 꼬여서 오거나, 해저 케이블이 끊겨 패킷이 사라지거나, 여러 개의 패킷들의 순서가 꼬일 수도 있다.

이는 [[네트워크]]의 복잡성을 줄이기 위한 [[네트워크#네트워크 가용성|가용성]] 측면의 동작 방법으로, 네트워크의 인텔리전스는 최종 노드 위에 위치하기 때문에 각 노드의 상태를 추적하거나 중앙 모니터링 등의 기능을 배제했다. 또한 [[Routing Protocol|라우팅]] 과정은 동적으로 이뤄지기 때문에 모든 [[패킷]]은 독립적으로 처리되고, 서로 다른 경로를 통해 동일한 목적지로 가는 결과가 나온다. 이로 인해 **IP는 언제나 최선의 전달만의 제공하며, 중간 노드에서는 해당 서비스를 신뢰할 수 없게 되었다.** 이 부분은 [[데이터그램 교환 방식]]에 의해  동작한다.

이런 결함 조건들은 참여하는 최종 노드(목적지)에 의해 감지되고 보상되어야 한다. 그래서 IP의 상위 계층 프로토콜은 안정성을 해결하는 역할을 수행한다.

이에 [[IPv4 헤더|IPv4의 헤더]]에서는 [[PDU|헤더]]자체의 오류가 없도록 보장하는 보호 장치 [[IPv4 헤더|체크섬]]을 제공한다. [[ICMP]]가 이를 이용해 오류 알림을 제공하긴 하는데, 라우팅 노드의 종단에 알릴 필요는 없다.

#### 비연결성
> Connection Lessness

[[IP - Internet Protocol|IP]]의 비연결성 특징은 위의 비신뢰적 특징을 연장한다. IP자체는 목적 서버의 [[패킷]]을 전송하기 전에 **송수신자 간의 연결을 미리 설정하지 않는다.** 위에서 말했듯, [[Routing Protocol|라우팅]] 과정은 동적으로 이뤄지기 때문에 모든 패킷은 독립적으로 처리되기 때문이다.

이로 인한 결과로 네트워크의 복잡도를 줄이고 빠른 속도로 전송이 이뤄졌지만, **목적지의 상태를 모르고 전달**되기 때문에 만약 목적지의 서버가 다운된 상태라도 전송은 이루어지고, 그 후 폐기된다.

## IP의 주소
> IP Address

IP는 일종의 [[식별자]]의 역할도 같이 하는데, 이 식별자 번호를 **IP 주소**라고 한다. 이를 이용해 **송 / 수신자는 서로를 특정할 수 있고, 이 주소가 없다면 통신이 불가능하다.** 줄여서 IP라고도 하지만, 엄밀히 말하면 IP는 [[프로토콜]]이고, IP 주소는 [[식별자]]다. 이 IP 주소를 외우는건 어렵기 때문에 [[DNS]]가 이들에게 이름을 부여해 일종의 전화번호부 같은 역할을 한다.

IP주소를 부여하는 방법으로는 정적인 방법과 동적인 방법으로 나뉜다. 보통의 네트워크에서 정적은 수동 입력을 의미하는 경우가 많은데, IP 주소에서도 똑같이 직접 IP의 주소를 입력하는 것을 정적 주소 할당 혹은 고정 IP 할당이라고도 한다. 

동적 IP 주소 할당은 [[DHCP]]를 이용한다. 요즘 [[운영체제 - OS]]에서는 기본적으로 DHCP사용이 선택되어있어 네트워크에 새로운 디바이스를 연결할 때 IP주소를 정적으로 입력하지 않는다. 그렇다고 네트워크에 참여하는 모든 디바이스가 DHCP를 사용하는건 아니다. 서버, 라우터 등 주소가 변하면 안되는 디바이스들은 고정 주소로 구성한다.

#### IPv4의 주소 체계
> IPv4 Address Structure -> [[IPv4 주소]]

```
192.168.10.1/24
```

**[[IPv4 주소|IPv4의 주소는]] 8비트 4옥텟, 총 32비트**로 이루어져 있으며 점으로 구분되고 10진수로 이루어져 있다.
과거 [[클래스 기반 네트워크|클래스풀]] 네트워크를 기반으로 총 5개의 공인 클래스와 3개의 사설 클래스로 이루어져 있으나, [[클래스 리스 네트워크|클래스 리스]]기반인 현재는 사설 클래스만이 그 흔적을 지니고 있다.

#### IPv6의 주소 체계
> IPv6 Address Structure -> [[IPv6 주소]]

```
2001 : 0DC8 : E004 : 0001 : 0000 : 0000 : 0000 : F00A
```

**[[IPv6 주소|IPv6의 주소는]] 16비트 8옥텟, 총 128비트**로 이루어져 있다. 기본적인 표기법은 콜론으로 구분하고 16진수로 이뤄지지만, 특징적인 표기법이 존재한다. 자세한 내용은 해당 문서 참조. 사실상 무한개의 주소를 표기할 수 있다.
