# IPv4 헤더
> IPv4 Header

[[패킷]]의 [[메타데이터]]를 가지고 있는 헤더. 일반적으로 생각하는 [[IPv4|IP주소]]와는 다른 개념이다. IPv4주소는 호스트를 식별하기 위한 주소 그 자체를 나타내는 32비트 데이터고, **IPv4 헤더는 패킷의 제어 정보를 담는 데이터**이다. 해당 패킷의 생존 시간, 버전, **호스트 간 주소 지정 및 [[Routing Protocol|라우팅 프로토콜]]의 정보 등을 저장**한다.

최소 20바이트, 최대 60바이트까지 확장이 가능하다.

---
## IPv4 헤더의 전체 구조
> IPv4 Header Structure

![[IPv4 헤더.png]]

옵션을 제외하고 5개의 헤더로 구성되어 있다. 각 헤더는 4바이트(32비트)로 이루어져 있으며 전체 헤더의 최소 크기는 20바이트(160비트), 최대 60바이트(480비트)이다.

총 10개의 필드로 이루어져 있으며 각 필드의 내용은 아래와 같다.

---
## IPv4 헤더의 필드(필수)
IPv4 헤더의 필수적인 필드. 제거하면 안된다.
총 5개의 헤더로 구성되어 있으며 각 헤더는 4바이트로 이루어져 있고 총 20바이트.

#### 버전(4Bit)
> Version

IP 버전을 구분한다. 값은 4와 6으로, IP버전과 동일한 값을 지닌다. 

- 버전 표기
	- [[IPv4]]: 4 -> `0100`
	- [[IPv6]]: 6 -> `0110`

#### 헤더 길이(4Bit)
> Header Length

**헤더의 전체 길이**를 4비트 단위로 나타낸다. 기본값은 5. 즉 20바이트를 의미한다. 만약 옵션 필드가 추가되면 늘어난다.

#### 서비스 타입(8Bit)
> Type of Service

6비트의 DSCP + 2비트의 ECN으로 구성된다.

이 때 ECN은 [[TCP 헤더]]에서 혼잡 제어 용도로 사용한다.

#### 총 길이(16Bit)
> Total Length

[[패킷]]의 **전체 길이를 표시**한다. 이 때 헤더부터 데이터의 끝까지의 길이 모두를 말한다. 총 `65,535`바이트까지 표현이 가능하다.

#### 패킷 식별 번호(16Bit)
> Identification

[[패킷]]의 조각화 시 같은 그룹으로 식별하기 위한 번호로, 조각난 패킷을 재조립할 때 사용한다.

#### IPv4 플래그(3Bit)
> Flag

[[패킷]]의 조각화를 제어하는 플래그. 첫 번째는 언제나 `0`으로 예약되어 있고, 두 번째는 조각화 금지 플래그, 세 번째는 조각 여부 확인 플래그이다.

#### 데이터 위치(13Bit)
> Fragment Offset

조각난 데이터의 상대적인 위치를 표기한다. 단위는 8바이트.

#### 생존 시간(8Bit)
> Time To Live -> [[TTL#IP 헤더의 TTL|TTL]]

[[패킷]]의 생존 시간을 표기한다. 패킷이 폐기되지 않고 평생 네트워크를 떠돌아다니는 일(루핑)을 방지한다.
하나의 [[Router|라우터]]를 지날 때 마다 1씩 감소하며, 0이 되는 순간 라우터는 해당 패킷을 폐기한다.

#### 프로토콜(8Bit)
> Protocol

IPv4의 페이로드가 어떤 [[프로토콜]]을 포함했는지 표기한다.

- 프로토콜의 값
	- [[ICMP]] -> 1    ->`0000 0001`
	- [[IGMP]] -> 2    ->`0000 0010`
	- [[TCP]]    -> 6   ->`0000 0110`
	- [[UDP]]   -> 17 ->`0001 0001`

#### 헤더 체크섬(16Bit)
> Header Checksum -> [[체크섬#IPv4 헤더 체크섬|IPv4 헤더의 체크섬]]

**헤더의 오류를 검출**하기 위한 필드로, 수신자가 검증 후 오류가 있으면 폐기한다. [[페이로드]]의 오류는 검출하지 않는다.

#### 송 / 수신자의 IP 주소(32Bit)
> Source / Destination IP Address

출발지(송신자) 혹은 목적지(수신자)의 [[IPv4 주소]]

---
## IPv4 헤더의 필드(옵션)
옵션 값은 송신자의 마음대로 지정한다. 단, 헤더의 총 길이가 60바이트를 넘어갈 수는 없다.
주로 사용 빈도는 낮지만, 특별한 기능을 제공하는 필드들이다.
