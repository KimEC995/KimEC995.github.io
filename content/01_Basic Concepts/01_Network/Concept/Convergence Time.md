# 변경 사항 적용 시간
> Convergence Time

[[네트워크|네트워크]]의 변경 사항(링크 다운, 경로 변동 등)이 발생했을 때, 모든 [[Router|라우터]]가 이를 반영해 **정확하고 일관된 라우팅 정보를 가지게 되기까지 걸리는 시간을 의미**한다. 수렴 시간이라고도 한다.

예를 들어 모두가 잘 알고 서로 잘 통신하던 라우터 마을이 있을 때(이 때 [[라우터의 최적 경로 선출 방식의 차이|최적 경로]]는 A와 B를 바로 이어주는 가운데 링크)

![[Convergence_Time(1).png]]

천재지변으로 기존 최적경로가 끊어졌다.

```bash
%LINEPROTO-5-UPDOWN: Line protocol on Interface Serial0/0/0, changed state to down
```

![[Convergence_Time(2).png]]

이후

1. 이를 감지한 라우터들은 [[Routing Protocol|라우팅 프로토콜]]을 통해 서로 정보를 주고받는다(ex. 누가 제일 빠르니, 누가 제일 우선이니..)
2. 이후 새로운 최적 경로를 설정한다.
3. [[라우팅 테이블]]을 갱신한다.
4. 이 모든 과정이 완료되어 **모든 라우터가 최신 상태로 일치**한다.

이 때 까지 소요되는 시간이 컨버젼스 타임이다. 라우팅 프로토콜의 종류에 따라 컨버젼스 속도가 밀리 초에서 몇 분 까지의 차이가 난다.

만약 컨버젼스 속도가 지나치게 느리면 그 사이 루핑, [[Packet|패킷]] 손실, 지연 등의 문제가 발생하기 때문에 컨버젼스 속도는 프로토콜의 신뢰성과 안정성에 직접적인 영향을 끼친다.

실무적 관점에서 보면 너무 빠른 시간도 딱히 장점은 아닌데, 순간적으로 다운된 후 대박 빨리 복구된 라우터가 존재할 경우 이 라우터의 정보를 교환하느라 또 자원을 낭비하기 때문이다. 그래서 수렴 시간은 기본값으로 설정된 시간이 가장 이상적이다.
