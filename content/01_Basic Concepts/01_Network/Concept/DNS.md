# DNS
> Domain Name Service

- **프로토콜**: [[UDP]] / 특수: [[TCP]]
- **포트 번호**: [[포트 번호|53번]]
- **계층**: [[OSI 7 Layer & TCP,IP 4 Layer#Application Layer|응용 계층(L7)]]
- **관련 공격**: [[DNS 스푸핑]]
- **역할**: IP주소의 주소록

**DNS는 [[IP - Internet Protocol#IP의 주소|IP 주소]]를 도메인 이름으로 바꿔주는 서비스**이다. 외우기 힘든 IP 주소보다는 이름을 외우는게 쉽기 때문에 생겨났다. DNS를 운영하는 서버를 **DNS 서버** 혹은 네임서버(Name Server) 라고 한다. 

계층적 구조로 인해 도메인을 오른쪽부터 왼쪽으로 구분해 처리한다. 자세한 내용은 [[도메인 계층]]을 확인.

포트 번호는 일반적으로 UDP의 53번 포트를 사용하지만, 특수한 경우 [[TCP]]의 53번 포트를 사용하기도 한다.

> [!note] 프로토콜 UDP? TCP?
> 사실 최근엔 TCP를 더 선호하는 추세라 UDP / TCP를 굳이 결정하긴 애매하다.... 
> 
> 왜냐면 TCP 53번을 사용하는 경우는 `512bytes`를 넘어가면 TCP로 전환되는데 최근엔 대부분 넘어가니까. 
> 근데 보안기사나 전통적인 시험에선 TCP는 특수한 경우만 쓴다고 UDP가 정답이고 TCP는 오답처리 하는 경우도 있어서 이건 좀 주의해야할듯?


주 DNS와 보조 DNS로 나뉘는데, 일반적으로 주 DNS가 메인으로 동작 / 보조 DNS는 백업용으로 동작한다. 가끔 둘 다 동시에 쿼리하다 먼저 응답하는 DNS의 정보를 채택하는 경우도 있다.

## DNS 관련 용어 정리
> DNS Terms

- **host 파일**
	- 클라이언트가 소유하고 있다.
	- 위치
		- windows: `C:\windows\system32\drivers\etc\hosts`
		- Linux: `/etc/hosts`

- **재귀 질의**
	- DNS 서버가 **클라이언트 대신 정확한 IP 주소를 끝까지 책임지고 찾는 것**
	- 자세한 내용은 [[DNS#3. DNS 서버의 재귀 질의 수행|재귀 질의 수행]] 부분을 확인

- **반복 질의**
	- 재귀질의와는 반대로 **질의의 주체를 넘기는 것**
	- 재귀질의시 `root DNS 서버`가 질의를 던졌을 때, 응답을 보내며 주체를 넘기는 행동이다.

- **zone 파일**
	- DNS의 영역을 설정하는 텍스트 파일.
	- 자세한 내용은 [[zone 파일]]을 확인할 것.

## DNS 서버의 쿼리 순서
DNS는 서비스고, DNS를 제공하는건 DNS 서버이다. 이 DNS 서버는 어떤 순서를 거쳐 IP 주소와 도메인네임을 교환해줄까.

예시를 위해 도메인 네임은 `www.test.co.kr`로 설정.

#### 1. 클라이언트의 질의 시작
> Client Query

![[DNS(1).png]]

사용자가 `www.test.co.kr` 로 접근 시작할 때 클라이언트 디바이스는 우선 내부의 캐시와 파일을 확인한다.

이 때 클라이언트의 디바이스(OS / Browser)는 다음과 같은 순서로 `www.test.co.kr`의 주소를 찾는다.

1. 브라우저의 캐시
2. OS의 DNS 캐시([[ipconfig|ipconfig /displaydns]])
3. `host`파일 확인

만약 이 3개의 위치에 없다면 이후 DNS 서버에게 질의를 보낸다.

#### 2. DNS 질의 메시지 전송
> Query Message

![[DNS(2).png]]

클라이언트가 지정된 로컬 DNS 서버에게 쿼리문을 보낸다.

```
질문: www.test.co.kr의 A 레코드를 알려주세용
```

이 때 클라이언트의 포트 번호는 랜덤 / 서버의 포트 번호는 53번을 사용한다.

#### 2. DNS 서버의 질의 처리: 데이터 확인
> Check Data

![[DNS(3).png]]

질의를 수신한 DNS 서버는 우선 최근에 질의 된 내용이 있는지 확인을 위해 내부 [[캐시 메모리 - Cache Memory|캐시 메모리]]를 조회한다. 만약 조회 결과가 없다면 이후 로컬의 [[zone 파일]]의 데이터를 확인한다. 

#### 3. DNS 서버의 재귀 질의 수행
> DNS Recursive query

이후 설정에 따라 재귀 질의 수행 여부를 판단하는데, 여기선 수행한다고 가정한다.

![[DNS(4).png]]

#### 4. 응답 전송
> Send ACK

![[DNS(5).png]]

로컬 DNS는 찾은 주소를 다시 클라이언트에게 보낸다.

#### 5. 서비스 접근

![[DNS(6).png]]

주소를 알아낸 클라이언트는 서비스 서버에 접근한다. 이후 [[HandShaking]]후 통신을 진행한다.
