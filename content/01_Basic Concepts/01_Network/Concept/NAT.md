# NAT
> Network Address Translation

- **[[라우터]]의 기능들 중 하나**
- **관련 계층**: [[OSI 7 Layer & TCP,IP 4 Layer|네트워크 계층(L3)]]

![[NAT(4).png]]

**라우터를 기준으로 [[사설 네트워크|사설망]]에서는 [[사설 IP와 공인 IP|사설 IP]]를 사용하고, [[외부 네트워크|외부망]]으로 나갈 때에는 [[사설 IP와 공인 IP|공인 IP]]주소로 변환돼서 나가게 하는 기술.** 일반적으로 [[공유기|라우터(공유기)]]에서 사용하지만 서버나 방화벽 장비도 지원한다.

본디 [[IPv4#IPv4의 주소 고갈 문제|IPv4의 주소 고갈 문제]]로 인해 대두되었으나 정적 / 동적 NAT는 이를 딱히 해결하지는 못했고, PAT 기술로 해결했다. 

주소 부족 해결 뿐만 아니라 다양한 해결책으로 사용하기도 한다. [[정보보안]]적인 시각에서 NAT는 실제 출발지 주소가 변환되어 외부로 나가기 때문에 어느정도 **방화벽 역할도 겸한다.** 물론 노력하면 접근할 수 있기 때문에 완벽한 보안은 아니다. 경제적인 시각에선 여러 사용자가 동시에 같은 이름으로 인터넷에 접근할 수 있다.

성능적인 문제는 IP주소에 변화가 생기기 때문에 [[IPv4 헤더]]의 송 / 수신 주소지가 변경된다. 이 변경으로 인해 내부의 [[체크섬]]도 재계산해야하고 결과적으로 네트워크의 성능에 영향을 미친다. 또한 한 번에 너무 많은 접속자가 몰릴 경우 결국엔 하나의 IPv4 주소를 사용하기 때문에 네트워크 접속 속도가 저하될 수 있다.

[[IPv6]]의 경우 보유 가능한 주소가 사실상 무한에 가깝고 연결 방식이 다르기 때문에 NAT를 잘 쓰지 않는다.

## NAT의 종류
NAT는 정적, 동적, PAT 세 가지로 나뉜다.
IPv4 주소 문제로 PAT가 대두되었지만, 정적 동적 NAT도 상황에 따라 다르게 사용한다.

#### Static NAT - 정적 NAT
> 1:1 대응

사설 IP와 공인 IP의 1:1 Mapping

![[NAT(1).png]]

[[DNS|DNS 서버]] 등 호스트가 변하면 안되는 경우, 즉 **외부에서 내부로 들어가는 경우 사용한다.** 단, 1:1 Mapping 방식이기 때문에 사설 IP가 삭제되어도 할당된 공인 IP는 유지된다.

#### Dynamic NAT - 동적 NAT
> N:M 대응

사설 IP 주소 그룹(Pool)에서 하나의 공인 IP 주소 그룹(Pool)

![[NAT(2).png]]

**주로 사설망에서 인터넷에 접속할 때 사용한다.** 사설 IP의 수가 공인 IP의 수보다 많을 수는 없다. 즉, 최대 접근 가능량은 공인 IP의 수와 동일하다.

**하나의 공인 IP 그룹에 너무 많은 사설 IP가 몰리면 자원 분배 문제로 인해 속도가 많이 저하된다.**

#### PAT
> Port Address Translation -> 1:N 대응

**다수의 사설 IP 주소를 1개의 공인 IP로 변환시켜 외부와 통신이 가능하게 하는 기술**

![[NAT(3).png]]

최대 64,000개 까지 하나의 공인 IP로 연결할 수 있다. 물론 전부 다 연결하면 느려지는데, [[NAT#Dynamic NAT - 동적 NAT|동적 NAT]]처럼 하나의 자원을 분배해서 느려지는게 아니라 순수하게 연산 문제로 느려진다.

**각 호스트마다 [[포트 번호]]로 구분하며 이를 통해 외부와 통신한다.**

[[00_CISCO Packet Tracer|CISCO]]에서는 이를 `Overload`라고 부른다.

라우터에서는 공인 IP주소에 유일한 송신지의 포트 번호를 할당해 내부 호스트별 [[패킷]]을 구분할 수 있다.
