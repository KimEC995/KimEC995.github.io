# TCP 헤더
> TCP Header

세그먼트 헤더가 더 올바른 단어이지만, UDP와의 구분을 위해 일단 TCP헤더라고 부르겠다.

[[세그먼트]]의 [[메타데이터]]를 가지고 있는 헤더. [[패킷]]의 [[페이로드]] 중 앞부분이다.

중간에 있는 TCP Flag 필드를 사용해 [[HandShaking#3Way Handshaking|3Way-Handshaking]]을 할 수 있거나 혹은 [[목적지 스캐닝 기법]]에서 적극 활용할 수 있다.

- 크기
	- 기본 필드: 20Byte
	- 옵션 필드: 40Byte 까지
	- 최대 헤더 크기: 총 60Byte 까지

일반적으로 20~32 Byte가 많이 보인다.

## TCP 헤더의 전체 구조
> TCP Header Structure

![[TCP 헤더(1).png]]

옵션을 제외하고 5개의 헤더 = 9개의 필드 + 8개의 플래그 로 이루어져있다.

#### 주의 사항!!
> [!note] RFC 3540으로 인한 TCP Flags의 변화
> 참고로 TCP Flags는 전통적으로 6~8비트라고 알려져 있지만 2003년 부터 2017년 까지 RFC 3540 표준에선 9비트로 표기했었다. `NS`플래그가 추가되었기 때문이다.
> 단, 이는 실험적 플래그였고 2017년 이후에는 다시 0으로 변화되어 예약은 다시 4Bit, Flags는 8Bit로 변경되었다.
> 그래서 가끔 블로그나 책에선 6 / 8 / 9 등으로 바뀌는데 **현재(2025년 5월)에는 8개로 확정**되었다.
> 
> 만약 현재 포스트와 실제 TCP 헤더의 정보가 다르다면, 과거의 정책을 사용하거나 해당 포스트가 과거가 된 경우 중 하나일테니 해당 정책을 확인하자.

위와 같이 정책에 따라 헤더의 길이나 플래그의 변동이 있을 수 있다. 따라서 이 포스트에선 2025년 기준 가장 최신 TCP 정책인 [RFC 9293](https://datatracker.ietf.org/doc/html/rfc9293)을 중심으로 작성한다. 다만 시험이나 기타 환경에선 과거 정책을 사용할 수도 있으니 언제나 **사용 정책을 중심으로 판단**할 것.

## TCP 헤더의 필드(필수)

#### 송 / 수신 포트 번호(16Bit)
> Source / Destination Port

송 / 수신자의 [[포트 번호]]를 표기한다.

양쪽 호스트 내의 종단 [[프로세스- Process|프로세스]]를 식별한다.

#### 시퀀스 번호(32 Bit)
> Sequence Number

TCP는 데이터를 작은 [[세그먼트]] 단위로 나누어 전송한다. 이때에 **각 세그먼트에 시작 바이트의 번호를 부여**하는데, 이를 시퀀스 번호라고 한다. 이는 수신자가 데이터의 순서를 정할 수 있게 하고, **손실 여부를 확인**할 수 있도록 돕는다.

#### 응답 번호(32 Bit)
> Acknowledgement Number

수신자가 다음에 기대하는 바이트의 시퀀스 번호. 즉 **수신 확인**을 한다. 단, [[TCP 제어 플래그#ACK|ACK 플래그]]가 활성화 되었을 때만 유효하다.

#### 오프셋(4 Bit)
> Offset

TCP헤더는 가변길이를 가지므로, 수신자는 어디까지 헤더이고 어디까지 데이터인지 판단해야 한다. 따라서 **오프셋 값으로 헤더의 길이를 표현**한다.

```
오프셋 = 헤더의 길이 / 4
```

만약 TCP 헤더에 옵션이 없다면 
1. 헤더의 길이는 20바이트가 된다. 
2. `20/4`로 오프셋은 5의 값을 가진다.
3. 이는 `0101`으로 표현한다.

만약 옵션이 있을 때
1. 이 길이가 32바이트라고 가정하면
2. `32/4`로 오프셋은 8을 가진다.
3. 이는 `1000`으로 표현한다.

#### 예약 필드(4 Bit)
> Reserved

현재 사용하지 않지만, 미래를 위해 확장 가능성을 남겨둔 필드. 현재는 사용하지 않기 때문에 값은 항상 0으로 표시한다. `0000`

중간에 하나 `NS`가 추가되어 3Bit로 바뀐 적도 있었지만, 현재 `NS`플래그는 사용하지 않는 것으로 간주해 항상 0으로 표기해야 한다.

#### TCP 제어 플래그(8 Bit)
> TCP Flags -> [[TCP 제어 플래그]]

블로그 혹은 책마다 제어 플래그의 수가 다르다. 이는 TCP 정책에 따라 다른 것이니 큰 틀에서만 확인하자.

자세한 플래그의 정보는 해당 포스트 참조.

#### 윈도우(16 Bit)
> Windows

[[슬라이딩 윈도우]]의 [[01_Basic Concepts/05_Computing Science/buffer|버퍼]] 크기를 표기한다.

#### TCP 체크섬(16 Bit)
> TCP Checksum -> [[체크섬#TCP 헤더 체크섬|TCP 체크섬]]

TCP헤더와 [[페이로드]]의 오류 검출을 위한 체크섬.

#### 긴급 포인터(16 Bit)
> Urgent Pointer

[[TCP 제어 플래그#URG|URG 플래그]]가 활성화 됐을 때 긴급 데이터의 끝 위치를 표기한다.

## TCP 헤더의 필드(옵션)
> Options

선택적 기능([[슬라이딩 윈도우|전송 윈도우]]의 크기 제어 등) 들을 포함한다. 주로 사용 빈도는 낮지만, 특별한 기능을 제공하는 필드들이다.

길이는 가변적이다.

#### 패딩
> Padding

길이는 가변적이다. 만약 헤더에 옵션이 포함되면 헤더 전체 크기가 32비트가 되도록 정렬하는 채움 데이터.
